# Цели разработки FrameTracker

Источник: [PRODUCT-IDEAS.md](PRODUCT-IDEAS.md). Дата: 13 ноября 2026.

## Как пользоваться

Каждый пункт FT — отдельная цель для передачи в пайплайн: описание → спецификация и план → реализация → проверка. Передавай ID и соответствующий раздел этого файла. Зависимости указаны явно; критерии ниже задают результат, а детали решения уточняются в спецификации.

Отмечай цель в общем списке после выполнения всех её критериев и общей проверки готовности. Рядом добавляй ссылку на изменение в `openspec/changes/` или его архив, а также на результаты проверки. Если цель отложена, оставляй чекбокс пустым и записывай причину. Выполнение исследовательской цели означает получение вывода, а не обязательную разработку функции.

## Карточки для передачи в пайплайн

### FT-01. Неизвестный запас

**Зачем:** не выдавать отсутствие введённых данных за реальную нехватку.

**Результат:** пользователь видит, для каких ресурсов количество известно, а какие ещё не проверены. Источник: D4, D2. Зависимостей нет.

Критерии готовности:

- [x] Неизвестный запас визуально и в расчётах отличается от явно введённого нуля.
- [x] Для неизвестного запаса показывается потребность и необходимость уточнить количество, а не достоверный дефицит.
- [x] Можно указать количество и снова пометить его неизвестным.
- [x] Старые явно сохранённые количества сохраняются; отсутствующие значения не превращаются автоматически в подтверждённые нули.

Подтверждение: [OpenSpec](openspec/changes/archive/2026-11-13-personal-farming-assistant/tasks.md), [проверки](openspec/changes/archive/2026-11-13-personal-farming-assistant/validation.md).

### FT-02. Следующее действие

**Зачем:** отвечать на вопрос «что сделать для этой цели сейчас».

**Результат:** карточка действия для выбранного активного фрейма на основе его рецепта и личного прогресса. Источник: P1. Зависимость: FT-01.

Критерии готовности:

- [x] Для незавершённой цели видны ближайшее препятствие, конкретное действие и его связь с целью.
- [x] Различаются получение чертежа/компонента, добыча ресурса и готовность к изготовлению; учтены вложенные рецепты.
- [x] После изменения прогресса действие пересчитывается; завершённая цель не предлагает фарм уже закрытых требований.
- [x] При неизвестных запасах предлагается уточнение; при отсутствии источника явно сообщается о нехватке данных.
- [x] При отсутствии целей есть понятный переход к их выбору. Совет не объявляется оптимальным маршрутом.

Подтверждение: [OpenSpec](openspec/changes/archive/2026-11-13-personal-farming-assistant/tasks.md), [проверки](openspec/changes/archive/2026-11-13-personal-farming-assistant/validation.md).

### FT-03. Справка об источнике

**Зачем:** дать достаточно информации для начала выбранной активности без обязательного перехода в вики.

**Результат:** краткая справка рядом с действием и проверяемое происхождение данных. Источник: D3 и минимальная часть E4. Зависимость: FT-02.

Критерии готовности:

- [x] У источника указаны награда, место/способ получения, известные условия и ротация, когда она применима.
- [x] Доступны ссылка на источник сведений и дата их проверки/обновления; отсутствующие сведения помечены явно.
- [x] Определён и перечислен начальный набор покрытых целей; для остальных есть честное состояние неполных данных.
- [x] При обновлении каталога выявляются сломанные ссылки между предметами, рецептами и источниками; результат проверки доступен разработчику.
- [x] Отсутствие записи об источнике не трактуется как доказательство невозможности получить предмет.

Подтверждение: [OpenSpec](openspec/changes/archive/2026-11-13-personal-farming-assistant/tasks.md), [проверки](openspec/changes/archive/2026-11-13-personal-farming-assistant/validation.md).

### FT-04. Быстрая запись результатов

**Зачем:** уменьшить время ведения трекера после игры.

**Результат:** обновление нужных данных непосредственно из плана цели. Источник: D2. Зависимости: FT-01, FT-02.

Критерии готовности:

- [x] Из плана можно отметить получение чертежа, готовый компонент и изменение количества нужного ресурса без поиска по всему каталогу.
- [x] После записи пересчитываются дефицит и следующее действие, а существующая отмена восстанавливает предыдущее состояние.
- [x] Запись ранее изготовленного компонента не списывает ресурсы незаметно; правило учёта понятно до изменения.
- [x] Не требуется вводить ресурсы, не относящиеся к выбранным целям.
- [x] Если добавляется операция нового крафта со списанием, её последствия показаны явно и отменяются целиком. Такая операция необязательна для первого выпуска.

Подтверждение: [OpenSpec](openspec/changes/archive/2026-11-13-personal-farming-assistant/tasks.md), [проверки](openspec/changes/archive/2026-11-13-personal-farming-assistant/validation.md).

### FT-05. Начать и продолжить сборку

**Зачем:** получить пользу без полного заполнения коллекции и помнить контекст после перерыва.

**Результат:** единый вход в цикл «цель → действие → результат». Источник: D1, D4. Зависимости: FT-02, FT-03, FT-04.

Критерии готовности:

- [x] Новый пользователь может выбрать одного фрейма и отметить только относящиеся к нему компоненты и запасы.
- [x] При возвращении видны выбранная цель, её дефицит, следующее действие и последнее записанное изменение.
- [x] У цели можно сохранить, изменить и удалить личную заметку; она восстанавливается после перезапуска.
- [x] Входной экран использует существующие цели, а не создаёт второй независимый список.
- [x] Пустая и завершённая цель имеют понятные состояния и переход к следующей цели.

Подтверждение: [OpenSpec](openspec/changes/archive/2026-11-13-personal-farming-assistant/tasks.md), [проверки](openspec/changes/archive/2026-11-13-personal-farming-assistant/validation.md).

### FT-06. Проверка личной пользы

Закрыта по прямому подтверждению владельца 13 ноября 2026. Повторно не проверяем и не включаем в следующий цикл. [Журнал игровых наблюдений](openspec/changes/archive/2026-11-13-personal-farming-assistant/playtest.md) сохранён как исходный материал; неподтверждённые документами подпункты ниже не отмечены автоматически.

**Зачем:** выбрать следующее расширение по реальным затруднениям.

**Результат:** короткий отчёт наблюдений и решение о следующем шаге. Источник: раздел проверки пользы. Зависимость: FT-05.

Критерии готовности:

- [ ] Зафиксированы исходные наблюдения за текущим способом планирования и минимум три сессии с новым сценарием.
- [ ] Записаны время выбора занятия и обновления прогресса, обращения к вики по фарму, ошибки и причины отказа от советов.
- [ ] Проверено, достигается ли ориентир около минуты на запись результатов; отклонения объяснены, а не скрыты.
- [ ] Записано решение: исправить основной сценарий либо выбрать конкретное расширение FT-07–FT-15 с объяснением.
- [ ] Если игровые сессии ещё не проведены, цель остаётся незавершённой; проверка интерфейса не подменяет наблюдения за игрой.

### FT-07. Пересечения нескольких целей

**Зачем:** находить активности, полезные сразу нескольким сборкам.

**Результат:** группировка полезных наград по общим источникам. Источник: E1. Зависимости: FT-03, решение FT-06.

Критерии готовности:

- [ ] Для двух и более целей показаны общие источники, нужные награды и соответствующие цели.
- [ ] Совпадение названия миссии не объединяет несовместимые условия и ротации в одну обещанную награду.
- [ ] Завершённые требования исключаются; при отсутствии пересечений есть явное пустое состояние.
- [ ] До полной реализации сохранён ручной пример по реальным целям и вывод, повлиял ли он на выбор занятия.

### FT-08. Разные состояния коллекции

**Зачем:** различать текущий инвентарь, исторический прогресс и потребность получить ещё один экземпляр.

**Результат:** отдельные признаки владения, освоения, передачи Гельминту и намерения собрать повторно. Источник: P3. Зависимость: решение FT-06.

Критерии готовности:

- [ ] Отметки владения и освоения независимы; изменение владения не стирает освоение или историю Гельминта.
- [ ] Признак Гельминта доступен только применимым предметам.
- [ ] Дополнительный экземпляр можно поставить целью без сброса исторических достижений; дефицит относится к этому намерению.
- [ ] Старый признак завершения сохраняет прежний смысл и не превращается автоматически в освоение или передачу Гельминту.
- [ ] На примере десяти собственных фреймов записаны случаи, требующие новых статусов.

### FT-09. Личные ограничения фарма

**Зачем:** не повторять советы, которые игрок сейчас не может или не хочет выполнять.

**Результат:** пользователь исключает источник с причиной и может вернуть его. Источник: D5. Зависимости: FT-03, решение FT-06.

Критерии готовности:

- [ ] Можно указать «недоступно», «не хочу» или «позже с другом» для источника и снять ограничение.
- [ ] Причина сохраняется и видна; ограниченный источник не предлагается как обычный следующий шаг.
- [ ] При наличии альтернативы она показывается; если исключено всё, предлагается пересмотреть ограничения.

### FT-10. Собственные реликвии

**Зачем:** выбирать, что открыть для Prime-целей, исходя из личных запасов.

**Результат:** учёт количества и улучшения реликвий, связанных с активными целями. Источник: E3. Зависимости: FT-03, решение FT-06.

Критерии готовности:

- [ ] Можно ввести и изменить количество реликвий по уровням улучшения, не заполняя весь каталог.
- [ ] Видна связь имеющейся реликвии с недостающими частями; отдельно указано, когда реликвию ещё нужно добыть.
- [ ] Вероятности, если показаны, соответствуют улучшению и источнику данных; гарантированное число заходов не обещается.
- [ ] Израсходованную реликвию можно учесть с отменой; неизвестная доступность отличается от подтверждённого отсутствия источника.

### FT-11. Резервирование ресурсов

**Зачем:** понимать, какие сборки обеспечены запасами в выбранном порядке.

**Результат:** необязательное распределение ресурсов между целями. Источник: E2. Зависимости: FT-01, решение FT-06.

Критерии готовности:

- [ ] Игрок явно включает распределение по приоритету; понятно, чем оно отличается от общего дефицита.
- [ ] Общий запас распределяется один раз; для следующей цели виден остаток после предыдущих.
- [ ] Перестановка или удаление цели пересчитывает план, не изменяя фактические запасы.
- [ ] Неизвестный запас не представляется гарантированным резервом; завершённые цели не удерживают резерв.

### FT-12. План на сессию

**Зачем:** подбирать занятия под доступное время и настроение.

**Результат:** небольшой список занятий для выбранной цели, времени и типа активности. Источник: P2. Зависимости: FT-03, FT-09, решение FT-06.

Критерии готовности:

- [ ] Можно задать примерное время и предпочтения; каждое занятие объясняет вклад в цель.
- [ ] Учтены личные ограничения; при отсутствии подходящего занятия это сообщается явно.
- [ ] Длительность отмечена как оценка с понятным основанием; случайная награда не обещается в заданное время.

### FT-13. Почти завершённые цели

**Зачем:** помочь выбрать следующую сборку для завершения.

**Результат:** список близких к завершению целей с реальными препятствиями. Источник: P4. Зависимости: FT-01, решение FT-06.

Критерии готовности:

- [ ] Список показывает недостающие компоненты и ресурсы и объясняет порядок сортировки.
- [ ] Малое число недостающих частей не называется коротким или лёгким фармом без основания.
- [ ] Неизвестные запасы и закрытые требования показаны корректно; из списка можно открыть или выбрать цель.

### FT-14. Фарм или покупка

**Зачем:** выбирать способ получения недостающих торгуемых частей в рамках личного бюджета.

**Результат:** рядом доступны источники фарма, оценка покупки и бюджет. Источник: P5. Зависимости: FT-03, решение FT-06.

Критерии готовности:

- [ ] Для недостающих торгуемых частей показаны источники, цена с датой/статусом актуальности и ссылка на рынок.
- [ ] Можно задать бюджет; сумма необходимых покупок сравнивается с ним без автоматической покупки.
- [ ] Ошибка загрузки и неизвестная цена отличаются от нулевой цены.
- [ ] Покупка целого набора и отдельных частей сравнивается только при достаточных данных; цена предложения не выдаётся за гарантированную сделку.

### FT-15. Проверка ввода по скриншоту

**Зачем:** выяснить, уменьшает ли распознавание трудозатраты относительно FT-04.

**Результат:** ограниченный эксперимент и решение «разрабатывать / отложить». Источник: E5. Зависимости: FT-04, результаты FT-06.

Критерии готовности:

- [ ] Выбран один тип экрана наград и записаны поддерживаемые условия: язык, разрешение, ограничения примеров.
- [ ] На наборе реальных скриншотов записаны ошибки, время распознавания, исправлений и подтверждения в сравнении с ручным вводом.
- [ ] В прототипе распознанные результаты подтверждаются игроком до изменения прогресса; ошибку можно исправить.
- [ ] Зафиксирован вывод и условия следующего шага. Полноценная интеграция при положительном выводе оформляется новой целью.

### FT-17. Иконки материалов

**Зачем:** быстрее узнавать материалы в рецептах и списках ресурсов.

**Результат:** рядом с названием материала отображается его иконка из официальных ресурсов Warframe. Зависимостей нет.

Критерии готовности:

- [x] Иконки берутся из официальных ресурсов Warframe / Digital Extremes; для каждого ассета сохраняется ссылка на источник.
- [x] Иконки отображаются в рецептах, списках материалов и сводке потребности/дефицита в едином стиле и размере.
- [x] При отсутствии или ошибке загрузки иконки остаются читаемое название и аккуратная заглушка; расположение элементов не ломается.
- [x] Названия и количества материалов остаются доступны независимо от изображения.

### FT-18. Русские названия фреймов, поиск и сортировка

**Зачем:** русская версия должна позволять находить и просматривать фреймы по привычным игровым названиям.

**Результат:** при выборе русского языка названия фреймов отображаются на русском, поиск понимает русские названия, а алфавитная сортировка следует правилам русского языка. Зависимостей нет.

Критерии готовности:

- [x] В режиме RU используются официальные русские названия фреймов и их вариантов во всех местах интерфейса, где они показаны.
- [x] Поиск находит фреймов по полному русскому названию и его части без учёта регистра; «е» и «ё» считаются эквивалентными при поиске. Поиск по английским названиям также сохраняется.
- [x] Алфавитная сортировка в режиме RU выполняется по отображаемым русским названиям с учётом русской локали, включая корректный порядок «е»/«ё».
- [x] Переключение RU/EN сразу обновляет названия и алфавитный порядок с учётом текущего поискового запроса; выбранные цели и сохранённый прогресс сохраняются.
- [x] В режиме EN отображаются английские названия и применяется английский алфавитный порядок.

### FT-19. Закрытие меню и карточек по клику снаружи

**Зачем:** возвращаться к основному экрану без необходимости попадать в кнопку закрытия.

**Результат:** открытые меню и всплывающие карточки закрываются по клику во внешнюю область. Зависимостей нет.

Критерии готовности:

- [x] Клик вне открытого меню или всплывающей карточки закрывает её.
- [x] Клики внутри карточки, включая её кнопки, поля и прокрутку, не вызывают случайного закрытия.
- [x] При нескольких вложенных открытых слоях закрывается только верхний; клик не активирует элементы под ним.
- [x] Клик, открывающий меню или карточку, не закрывает её сразу же.
- [x] Существующие кнопки закрытия продолжают работать; закрытие не сбрасывает сохранённый прогресс.

### FT-20. Иконки реликвий

**Результат:** рядом с реликвиями отображаются узнаваемые изображения по аналогии с материалами FT-17.

Критерии готовности:

- [ ] Иконки добавлены в существующие списки и карточки реликвий в едином стиле с материалами.
- [ ] Название остаётся доступным; отсутствие изображения не нарушает отображение списка.

### FT-21. Визуальный вес сведений о каталоге

**Результат:** данные каталога и происхождение сведений меньше отвлекают от полезной информации.

Критерии готовности:

- [ ] Служебные подписи уменьшены или оформлены менее заметно с сохранением читаемости.
- [ ] Источники, даты обновления и сведения о неполных данных остаются доступными; требования FT-03 сохраняются.

### FT-22. Карточки инвентаря

**Результат:** каждый ресурс представлен квадратной карточкой с картинкой, текущим и требуемым количеством.

Критерии готовности:

- [ ] Есть кнопки +1, +10, +100 и −1, −10, −100; запас не уходит ниже нуля.
- [ ] Текущее количество выглядит как подчёркнутая кликабельная надпись и редактируется по нажатию, без постоянно видимого отдельного поля.
- [ ] Можно сохранить или отменить ввод; после изменения пересчитываются связанные потребности и дефицит.
- [ ] Сохраняются различие неизвестного запаса и нуля, сохранение прогресса и существующая отмена изменения.

### FT-23. Главная страница

**Результат:** стартовая страница кратко объясняет функционал и помогает перейти к нужному разделу.

Критерии готовности:

- [ ] Есть короткое описание возможностей и путеводитель по основным сценариям.
- [ ] Показаны число собранных фреймов и текущая Prime-ротация.
- [ ] Показаны актуальные циклы дня/ночи/температуры применимых открытых локаций.
- [ ] Для онлайн-сведений видны актуальность и состояние недоступности данных.

Возможное дополнение: информация о текущих событиях. Состав этого блока уточнить при подготовке спецификации; владелец обозначил его как необязательную идею.

### FT-24. Популярные билды Overframe

**Результат:** при открытии фрейма доступна ссылка на его самые популярные билды на overframe.gg.

Критерии готовности:

- [ ] В карточке фрейма есть понятная ссылка на популярные билды.
- [ ] Обычная и Prime-версия одного фрейма ведут на одну страницу.
- [ ] Соответствие фреймов страницам и способ перехода к популярным билдам проверены при реализации.

### FT-25. Новые категории коллекции

**Результат:** страницы с учётом коллекции по аналогии со страницей фреймов.

Критерии готовности:

- [ ] Добавлены категории: основное оружие, вторичное оружие, оружие ближнего боя, арчвинги, некромехи, основное оружие арчвингов и оружие ближнего боя арчвингов.
- [ ] Для каждой категории доступны каталог, просмотр предмета и отслеживание прогресса по образцу фреймов.
- [ ] Новые категории сохраняют свой прогресс и не нарушают существующую коллекцию фреймов.

### FT-26. Избранные фреймы

**Результат:** пользователь может сохранить любимых фреймов и открыть их отдельной вкладкой.

Критерии готовности:

- [ ] Фрейм можно добавить в избранное и удалить из него.
- [ ] Отдельная вкладка показывает избранные фреймы и понятное пустое состояние.
- [ ] Выбор сохраняется после перезапуска; избранное не подменяет список активных целей сборки.

### FT-27. Тема «Сталкер»

**Результат:** новая тёмная тема «Сталкер» становится темой по умолчанию.

Критерии готовности:

- [ ] Создана отдельная тема без изменения существующих тем и основной концепции интерфейса.
- [ ] При отсутствии сохранённого выбора применяется «Сталкер»; ранее выбранная пользователем тема сохраняется.
- [ ] Тема доступна в переключателе и обеспечивает читаемость основных экранов и состояний.

### FT-28. Поиск свободного порта при старте

**Результат:** приложение может запускаться, когда порт 4187 занят.

Критерии готовности:

- [ ] При занятом стартовом порте автоматически выбирается доступный порт.
- [ ] Интерфейс открывается по фактически выбранному адресу; режим без открытия браузера сохраняется.
- [ ] Проверены запуск со свободным и занятым портом, а также завершение приложения без оставшихся процессов.

### FT-29. Оптимизация фильтра Prime-частей

**Результат:** фильтр Prime-частей работает быстрее с сохранением корректного результата.

- [ ] Устранено выявленное узкое место; результат замера после изменения сопоставлен с исходным.
- [ ] Проверена корректность фильтра при переключении условий и обновлении данных доступности.

## Пересмотр очереди — 13 ноября 2026

FT-07–FT-15 остаются открытыми; FT-16 выполнена и не означает завершение FT-10: онлайн-доступность реликвий не учитывает собственный запас и улучшение.

Рекомендуемый следующий шаг — убрать трение при записи прогресса: всегда видимые статусы компонентов, свёрнутые по умолчанию рецепты, постоянный размер окна с внутренней прокруткой. Первый проход реализован в `public/app.js` и `public/style.css`; [проверен во внутреннем браузере на Ash, RU/EN и ширине 360 px](openspec/changes/archive/2026-11-13-component-status-polish/validation.md). Полная проверка остальных форм и вложенных рецептов ещё нужна. Это улучшение интерфейса, а не закрытие FT-08.

| FT-13 | Кандидат на ближайшее небольшое расширение: список незакрытых требований с объяснением сортировки и неизвестных запасов. |

## Общая готовность цели разработки

Применяется к FT-01–FT-05 и FT-07–FT-14; для исследований FT-06 и FT-15 достаточно их отчётов и критериев.

- Выполнены критерии карточки; записана ссылка на изменение и результаты проверки.
- Новый интерфейс доступен на RU/EN, включая пустые состояния и ошибки.
- Новые личные данные сохраняются после перезапуска и экспортируются/импортируются; старые сохранения не теряют прогресс.
- Изменения прогресса поддерживают существующую отмену, где она применима.
- Пройдены проверки затронутого поведения и обязательные проверки проекта; для изменения расчётов и сохранений проверены пограничные случаи.
- Обновлены затронутые спецификации и пользовательское описание. Невыполненные критерии не скрыты под общей отметкой «готово».
