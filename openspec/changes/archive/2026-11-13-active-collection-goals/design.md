## Context

Прогресс хранится в frames/stock, portable API сохраняет весь объект. Импорт нормализует только известные поля. Общий спрос уже правильно суммируется функцией demand.

## Goals / Non-Goals

Goals: выбрать цели, увидеть общий дефицит выбранного набора с однократным вычитанием запаса, изменить прогресс и отменить ошибку.

Non-Goals: автоматическое списание, резервирование ресурсов, автоплан фарма, таймеры, рыночные рекомендации. Порядок целей визуальный; он не резервирует ресурсы.

## Decisions

- Хранить goals как упорядоченный массив уникальных известных ID. Старое сохранение без поля означает пустые цели. Не выводить намерение пользователя из частично собранных фреймов.
- Нормализацию целей вынести в model.js и использовать при импорте. Неизвестные ID игнорировать, остальные данные сохранять по прежним правилам.
- Режим ресурсов по умолчанию «Мои цели», доступен общий режим. Пустая цель не заменяется молча всей коллекцией. Использовать существующий агрегатор demand для выбранного набора.
- Завершённая цель остаётся в списке с отметкой завершения, спрос по ней равен нулю. Можно убрать вручную. Фреймы без рецепта не добавлять.
- Одноуровневая отмена хранит снимок перед последним изменением frames/stock/goals или импортом; отмена сохраняет восстановленное состояние обычным механизмом. История не переживает перезапуск. Смена языка, фильтры, цены не создают историю.
- Кнопка отмены доступна вне dialog и внутри него; заблокирована при отсутствии снимка. Сообщения об ошибках сохранения остаются видимыми.

## Risks / Trade-offs

- Нет резервирования → рядом с целями пояснить, что порядок не распределяет запас.
- Ручные остатки могут устареть → не менять существующую семантику и не обещать точные советы.
- Старые версии приложения удалят новое поле при импорте → описать совместимость только в новой версии.

## Migration Plan

Добавочное поле goals, без смены ключа localStorage и API. Проверить старый импорт и round-trip новых целей. При откате экспортировать прогресс; старая версия игнорирует цели.
