## Context

См. [audit.md](audit.md), включая повторный аудит работающих экранов и UI-01–10. Vanilla JS без сборки frontend, три hash-раздела, отдельная модель данных. Цель этапа — дать пользователю сравнимый выбор. Решение принято: A, см. decision.md.

Повторная проверка подтверждает приоритет A: каталог начинается ниже первого экрана при 1281×720 и 360×800, а мобильный инвентарь скрывает дефицит справа. В любом направлении предусмотреть поиск материалов, явный сброс фильтров, единые стадии сбора и общую индикацию устаревших цен. Русские aliases поиска — отдельное расширение поведения, требующее обновления draft spec после выбора.

## Goals / Non-Goals

Цели: поднять рабочие действия выше, облегчить поиск незавершённых компонентов, сделать состояния данных явными. Сохранить узнаваемость и RU/EN.

Вне этапа: изменение production UI, миграция данных, аккаунты, автосинхронизация игры, новые алгоритмы фарма, очередь целей и смена frontend-стека.

## Прототипы

Открыть [prototypes/index.html](prototypes/index.html) напрямую в браузере. **Версия 2 переработана после живого аудита**, а не только перекрашена. Общие экраны Каталог / Инвентарь / Сводка переключаются во всех трёх вариантах. Работают поиск, стадии сбора, сброс, фильтр дефицита и открытие деталей. Запасы не редактируются; сохранений, API и доступа к реальному прогрессу нет. Цифры и источники условные. Каталог примера содержит 8 записей, Equinox — 3/9.

### Пересмотр направлений

- **A — основной кандидат:** компактная сетка и диалог; решает подтверждённые проблемы с наименьшей сменой взаимодействия. Удалён прежний декоративный заголовок «Твой арсенал» с лишним вертикальным пространством.
- **B — рабочий стол компонентов:** desktop-список и обзор выбранного фрейма рядом. На телефоне выбор открывает диалог вместо размещения рецепта под всем списком. Более сложен по фокусу и выбранному состоянию; преимущество перед A нужно проверять на задачах, оно не доказано аудитом.
- **C — коллекционный атлас с ограниченной декоративностью:** светлая палитра, портретные карточки немного выше A, но такой же компактный рабочий верх. Прежняя идея крупных витринных блоков понижена: она повторяла найденную проблему. Функционального превосходства C не заявляем; это выбор визуального характера при общей структуре.

Пересмотр приоритетов: P1 — доступ к поиску/результатам и мобильный дефицит; P2 — поиск материалов, стадии и пустые состояния, понятность устаревших цен; P3 — палитра и декоративные приёмы. Эти приоритеты общие для A/B/C.

Проверка v2: синтаксис prototype.js проверяется отдельно. Попытка открыть file:// через инструмент браузера отклонена политикой URL; визуальная и поведенческая проверка v2 не выполнена. Предыдущий живой аудит проверял действующее приложение, а не эти макеты. До реализации необходимо проверить v2 на 360/768/1281 px и сценариях выше.

## Decisions

- Не выбирать направление за пользователя. decision.md хранит явный gate.
- Оставить vanilla JS и существующую модель. Стили будущего варианта выразить токенами surface/text/border/accent/success/warning/error, spacing 4/8/12/16/24/32, системные шрифты с кириллицей.
- Общая навигация: Каталог / Инвентарь / Сводка, Данные и RU/EN остаются доступны. Для A/C сохраняется native dialog, для B потребуется отдельное решение о фокусе в немодальной desktop-панели.
- Каталог: заголовок, личный прогресс, поиск, тип и статус, результаты. Не добавлять новые вычисляемые «рекомендации фарма».
- Инвентарь: Материал / Нужно / Есть / Не хватает; переключатель дефицита и явный сброс фильтра. На mobile дефицит должен быть виден без горизонтальной прокрутки; в v2 используются строки с именем и тремя числовыми полями.
- Сводка: отдельно фактические расходы и оценка; coverage, дата цены, загрузка/остановка/ошибка остаются видимыми.
- Детали: владение → прогресс компонентов → выбранный рецепт/ресурсы/источники; цена и расходы в отдельном блоке. Equinox и crafted ingredients не упрощать до плоского checklist.

## Risks / Trade-offs

app.js перерисовывает DOM: возможна потеря фокуса/scroll при смене языка и состояния. Сохранять текущие механизмы возврата фокуса; проверять их после каждого изменения. Портреты внешние — сохранять fallback mark.svg и размеры контейнеров. Отсутствие цены не превращать в ноль. Mobile таблицы и длинные RU/EN подписи требуют проверки реальным контентом.

## Migration Plan

После выбора обновить decision/spec/tasks, затем сделать общий shell и каталог, отдельно детали и таблицы. Не менять storage keys, идентификаторы и API. Проверить npm test, portable assets и Windows smoke test. Откат будущего UI — возврат presentation-файлов без отката пользовательского прогресса.

## Validation / Open Questions

Сравнить на baseline и выбранном макете: найти Prime, найти незавершённый компонент, разобрать Equinox, изменить запас, различить неизвестную цену и фактические расходы, экспортировать прогресс. Записать ошибки и время; не заявлять ускорение без измерения.

Проверить 360/768/1440 px, RU/EN, zoom 200%, keyboard, Esc/возврат фокуса, длинные имена, пустой поиск, offline portraits, loading/stale/failed prices, сбой сохранения. Цель будущего UI: текстовый контраст 4.5:1, видимый focus, цели касания порядка 44 px, статус не только цветом.

Единственный необходимый следующий выбор: A, B или C. Блокирующих вопросов для подготовки материалов нет.

## Утверждённая реализация A

Пользователь выбрал A и разрешил коммит. Статичные прототипы заменены проверкой реального UI; B/C не реализуются. Поиск фреймов явно подсказывает английские названия, полный русский словарь aliases отложен. Native dialog сохраняет focus/scroll и вложенность; обзор компонентов позволяет перейти к нужному рецепту. Ошибка сохранения видна вне меню до успешной записи.
